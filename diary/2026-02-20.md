## Guide: Building a Microtuning M4L MIDI Effect

This section documents the complete architecture and all the pitfalls discovered while building a Max for Live device that applies microtuning (MTS-ESP) to any synth in Ableton. This serves as a reference guide for building similar tuning patches in M4L.

### The Problem

Ableton doesn't support VST3 MIDI effects natively. You can't just drop a VST3 MIDI effect before a synth like in Logic or Reaper. Max for Live is the only way to process MIDI inline before an instrument in Ableton.

### Why Not Just Use vst~ for MIDI?

Max's `vst~` object can host VST plugins, but **VST3 plugins cannot output MIDI through vst~**. Max drops `kLegacyMIDICCOutEvent` events and echoes the input MIDI instead. This is a fundamental limitation of how Max's VST3 hosting works.

**VST2 plugins CAN output MIDI through vst~** — this is how ODDSound's MTS-ESP MIDI Client works. Their VST2 handles all MIDI processing internally, and vst~ passes the retuned MIDI to its outlet 4. But VST2 is deprecated and we build VST3.

### The Solution: Parameter Bridge Architecture

Use the VST3 as a **data bridge only** (not for MIDI processing), and do all MIDI processing natively in Max:

```
┌─────────────────────────────────────────────────────────────────┐
│ M4L Device                                                       │
│                                                                   │
│  ┌──────────┐   ┌───────────┐   ┌──────────────┐   ┌──────────┐ │
│  │  midiin   │→  │ midiparse │→  │  js (MIDI    │→  │ midiout  │ │
│  └──────────┘   └───────────┘   │  processing) │   └──────────┘ │
│                                  └──────┬───────┘                │
│                                         ↑ tuning data            │
│  ┌──────────┐   ┌───────────┐   ┌──────┴───────┐                │
│  │ loadbang  │→  │  plug_vst3│→  │    vst~      │                │
│  └──────────┘   └───────────┘   │ (param bridge)│                │
│                  ┌───────────┐   └──────────────┘                │
│                  │ metro/uzi │→  poll 128 params                 │
│                  └───────────┘                                    │
└─────────────────────────────────────────────────────────────────┘
```

**Three tiers:**
1. **VST3 plugin** (`vst~`) — reads MTS-ESP tuning, exposes 128 `AudioParameterFloat` params (`cents_0`–`cents_127`, range -4800 to +4800 cents)
2. **Max `js` object** — receives tuning data on inlet 1, MIDI notes on inlet 0; handles MPE channel allocation + pitch bend calculation
3. **Max patch** — routes MIDI through `midiin` → `midiparse` → `js` → `midiout`, with `midiformat` for CC passthrough

### Critical Implementation Details

#### 1. JUCE VST3 Bypass Parameter (Off-by-One Bug)

**The single most important gotcha.** JUCE's VST3 wrapper automatically adds a **bypass parameter at index 0**. This shifts all your APVTS parameters by one:

| VST3 Index | Parameter |
|------------|-----------|
| 0 | Bypass (JUCE auto-added) |
| 1 | mode |
| 2 | mpePbRange |
| 3 | monoPbRange |
| 4–131 | cents_0 through cents_127 |

If your APVTS has 3 control params before the cents params, the offset for parameter polling is **+4, not +3**. We confirmed this by querying `get 3` in Max — it returned `0.010526`, which is exactly `(2 - 1) / (96 - 1) = 1/95` — the normalized default value of `monoPbRange` (default 2, range 1–96). This proved index 3 was monoPbRange, not cents_0.

**Polling chain:** `uzi 128 0` → `+ 4` → `prepend get` → `vst~` inlet → vst~ outlet 3 responds with `index normalized_value`

**Denormalization:** `unpack 0 0.` → left: `- 4` (MIDI note), right: `expr $f1 * 9600. - 4800.` (cents)

#### 2. Ableton `is_mpe` Flag

**Without this flag, Ableton normalizes all M4L MIDI output to channel 1**, which breaks MPE (channels 2-16).

Add `"is_mpe": 1` to the patcher JSON at the top level:
```python
patcher["is_mpe"] = 1
```

ODDSound's two M4L devices (MPE and non-MPE) are **structurally identical** — the only difference is `is_mpe: 1` vs `is_mpe: 0` and the default voice mode parameter. Setting `is_mpe: 1` is safe even when using Mono PB mode (channel 1 only) — Ableton just won't filter multi-channel data.

#### 3. Don't Reset Pitch Bend on Note Off

Resetting pitch bend to center (8192) on Note Off causes an audible pitch snap during the synth's release tail. The note is still decaying when the bend resets to 0 cents.

**Fix:** Simply don't send pitch bend on Note Off. The next Note On always sets pitch bend before sounding, so there's no stale data issue.

#### 4. vst~ Outlet Layout

For a default `vst~` (no audio channel arguments):
- Outlets 0-1: Audio (signal)
- Outlet 2: MIDI output (doesn't work for VST3)
- **Outlet 3: Parameter dump responses** (this is where `get` responses come)
- Outlets 4-7: Other messages

#### 5. Parameter Update Rate Limiting

Don't flood the host with parameter changes. In C++ `processBlock`:
- Update cents params **every 10 blocks** (not every block)
- Only update if change exceeds **0.01 cents threshold**
- Max polls with `metro 1000` (1 second interval) — tuning changes aren't real-time

#### 6. Plugin Loading in M4L

Use `plug_vst3 "Plugin Name"` (not `plug "Plugin Name"`). The `plug` message loads VST2; `plug_vst3` loads VST3. Wrong command crashes Max's dyld loader.

Add a delay before loading (`delay 2000`) and before starting parameter polling (`delay 3000`) to give Max time to initialize the vst~ and load the plugin.

#### 7. .amxd Binary Format

The `.amxd` format for Ableton distribution is:
```
ampf (4 bytes magic)
version (uint32 LE = 4)
mmmmmeta (8 bytes section tag)
meta_size (uint32 LE)
meta_data (meta_size bytes)
ptch (4 bytes section tag)
ptch_size (uint32 LE)
json_data (ptch_size bytes, null-terminated UTF-8 JSON)
```

The JSON is identical to the `.maxpat` content. Key M4L metadata in the patcher:
- `"amxdtype": 1835887981` (0x6D696469 = "midi") — declares as MIDI effect
- `"is_mpe": 1` — enables multi-channel MIDI output
- `"openrect": [0, 0, width, height]` — presentation dimensions
- `"openinpresentation": 1` — show presentation view in Ableton

#### 8. CC/Aftertouch Passthrough

Route `midiparse` outlets 1-6 directly to `midiformat` inlets 1-6 for passthrough of non-note MIDI data (CC, aftertouch, program change, pitch bend from controllers, channel). This bypasses the `js` object — only notes go through `js` for retuning.

### ODDSound Comparison

ODDSound's MTS-ESP M4L devices use **VST2** (not VST3), which has native MIDI output through `vst~`. Their approach:
- `midiin` → `midiparse @hires` → outlet 7 (raw bytes) → `vst~` → outlet 4 (MIDI out) → `midiout`
- The VST2 handles ALL MIDI processing internally (MPE channel alloc, pitch bend calc)
- No `js` objects, no parameter bridge needed
- `get -3` polls all params at once (not individual `get N` calls)
- Plugin loaded via `thispatcher` + `path` + `sprintf` for relative path resolution

Our approach is more complex because VST3's MIDI output limitation forces the parameter bridge + js architecture. But functionally equivalent.

## Bugs Fixed

### 1. Parameter Index Offset (+3 → +4)

**Symptom:** M4L device loaded, MIDI passed through, but all notes played at 12TET (no microtuning).

**Root cause:** JUCE's VST3 wrapper adds an automatic bypass parameter at index 0, shifting all APVTS parameters by one. Our `uzi 128 0` → `+ 3` → `prepend get` was querying indices 3–130, which mapped to `monoPbRange` + `cents_0`–`cents_126` (off by one, missing `cents_127`, including `monoPbRange` as if it were `cents_0`).

**Fix:** Changed `+ 3` to `+ 4` and `- 3` to `- 4` in both the polling chain and the denormalization chain. Now queries indices 4–131, correctly mapping to `cents_0`–`cents_127`.

**Diagnosis method:** Sent `get 3` manually in Max Console → returned `0.010526` = `1/95` = normalized default of monoPbRange (default 2, range 1–96). Confirmed bypass is at index 0.

### 2. Missing `is_mpe` Flag

**Symptom:** Mono PB mode worked perfectly, but MPE mode produced no sound or 12TET.

**Root cause:** Without `"is_mpe": 1` in the M4L patcher metadata, Ableton normalizes all MIDI output from the device to channel 1. MPE notes on channels 2-16 were being merged to channel 1, so the synth received all notes on channel 1 without per-note pitch bend.

**Fix:** Added `patcher["is_mpe"] = 1` in `generate_patch.py` post-processing.

**Discovery:** Compared ODDSound's MPE vs non-MPE `.amxd` files — structurally identical except for `is_mpe: 1` vs `0`.

### 3. Pitch Bend Snap-Back on Note Off

**Symptom:** Notes sounded correctly on Note On, but releasing a key caused an audible pitch snap back to 12TET during the synth's release tail.

**Root cause:** Both `processMonoPB` and `processMPE` in `mts_midi_effect.js` sent `outlet(0, 0xE0, 0, 64)` (pitch bend center) on Note Off. This reset the pitch bend while the note was still decaying.

**Fix:** Removed pitch bend reset from Note Off handlers in both modes. The next Note On always sets pitch bend before sounding, so there's no stale value issue.
