# 2026-02-25 — Session 42: Save/Load State to File (.tanghim)

## Summary

Implemented user-managed state persistence via `.tanghim` JSON files. Users can save and load the full plugin state (tuning system, slider positions, maqam selection, presets, reference frequency, per-note overrides, oscillator/hept mode) through native Save/Load file dialogs. This complements the existing DAW session persistence and disk preferences.

## Key Design Decisions

### File Format
Human-readable JSON with `.tanghim` extension. Includes a `"format": "tanghim-state"` marker and `"version": 1` for future compatibility. Mirrors `getStateInformation` data minus APVTS automation state (which is DAW-specific).

### Architecture: Three Persistence Layers
1. **DAW session** (`getStateInformation`/`setStateInformation`) — binary XML, tied to DAW project
2. **Disk preferences** (`settings.json` + `presets.json` in `~/Library/Tanghim/`) — persists across sessions
3. **User-managed files** (`.tanghim`) — shareable, human-readable, full state snapshots

### JUCE FileChooser (Async)
`FileChooser` must be stored as a member (`mutable std::unique_ptr<juce::FileChooser>` on NativeBridge) since the async dialog outlives the function scope. Native macOS dialogs work fine alongside WKWebView (system-level windows, not JUCE components).

### Two-Event Problem on Load
`loadTuningSystem()` fires `notifyTuningChanged()` twice during a file load:
1. First at the end of its own work (line 1110) — intermediate state with **cleared** maqam
2. Then from `restoreStateFromJson`'s completion lambda (line 982) — final state with **restored** maqam

The `afterSystemSwitchRef` callback mechanism was extended to support a `return false` protocol: the callback skips the first (intermediate) event and consumes the second (final) one. This ensures the JS side sees the fully restored state for modification tracking.

### Modification Detection on Load
After loading, the `afterSystemSwitchRef` callback compares each slot's `centsOffset` against the tuning system's default (`expectedVariant.midiCentsDeviation`) to populate `modifiedSlots`. This correctly renders cyan modified thumbs and the maqam name asterisk even when the user saved a modified (but not preset-stored) maqam state.

### Display Info Capture
`loadTuningSystem()` clears `currentMaqamDisplay`, `currentTonicDisplay`, etc. The `restoreStateFromJson` completion lambda must capture these as local variables before calling `loadTuningSystem` and restore them afterward — same pattern as `setStateInformation`.

## Files Changed

### C++
- **`PluginProcessor.h`** — Added `buildStateJson()` and `restoreStateFromJson()` public methods
- **`PluginProcessor.cpp`** — Implemented both methods. `buildStateJson()` uses `DynamicObject` + `JSON::toString()`. `restoreStateFromJson()` follows `setStateInformation()` pattern: parse JSON, restore presets, capture maqam state, async `loadTuningSystem()` with completion lambda
- **`NativeBridge.h`** — Added `mutable std::unique_ptr<juce::FileChooser> fileChooser`
- **`NativeBridge.cpp`** — Registered `saveStateFile` and `loadStateFile` native functions. `loadStateFile` returns `{ filename, hasMaqam }` object

### TypeScript
- **`useJuceBridge.ts`** — Added `saveStateFile()` and `loadStateFile()` bridge wrappers
- **`App.tsx`** — Added `handleSaveState`/`handleLoadState` handlers, wired to Load/Save menu bar buttons. `handleLoadState` sets up an `afterSystemSwitchRef` callback that skips the intermediate event and runs modification comparison on the final state. Extended `afterSystemSwitchRef` type to support `return false` (keep callback for next event)
