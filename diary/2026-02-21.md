## Session 19: Continuous Slider Tuning

### What Changed

**New concept: `centsOffset` as source of truth.** Previously, the frequency/cents tables were computed by looking up the selected variant's `midiCentsDeviation`. Now each chromatic slot has a `centsOffset` field that is the primary source of truth for tuning output. The existing `selectedIndex` is retained for snap marker highlighting, PAO name display, and preset recall.

### C++ Changes

**ActiveTuningState.h** — Added `double centsOffset = 0.0` to `ChromaticNoteVariants`. Modified `buildFrequencyTable()` and `buildCentsDeviationTable()` to read from `centsOffset` instead of looking up variant deviation.

**PluginProcessor** — Two new public methods:
- `setSlotCents(chromaticIndex, centsValue)` — clamps ±200, sets centsOffset, updates selectedIndex to nearest variant, clears maqam, updates MTS-ESP (no WebView push — lightweight for continuous drag)
- `finalizeSlotCents(chromaticIndex, centsValue)` — calls setSlotCents + notifyTuningChanged() (full state push on mouseup)

Synced `centsOffset` at all 7 existing `selectedIndex` write sites (loadTuningSystem, setSliderVariant, applyPreset, applyMaqamDegrees ×2, rebuildTuningStateFromCache) so that selecting a variant always updates centsOffset to match.

**NativeBridge** — Registered `setSlotCents` (fire-and-forget, returns `var()`) and `setSlotCentsFinalize` (returns full TuningState JSON). Added `centsOffset` to slot JSON in `buildTuningStateJson()`.

**Persistence** — `getStateInformation()` saves `"c0"`–`"c11"` properties. `setStateInformation()` reads with NaN sentinel for backward compatibility (old sessions derive centsOffset from selected variant).

### UI Changes

**NoteSlider.tsx** — Complete interaction rewrite:
- Free drag on track/thumb: mousedown → continuous `onCentsDrag` on mousemove → `onCentsDragEnd` on mouseup
- Snap marker click: `onVariantSelect` with stopPropagation
- Range expanded from ±100 to ±200 cents
- Thumb position and cents display driven by `slot.centsOffset`
- Ref-based `dragging` class toggle to disable CSS transition during drag

**NoteSliderBank.tsx** — Replaced single `onSliderChange` prop with three callbacks: `onVariantSelect`, `onCentsDrag`, `onCentsDragEnd`.

**App.tsx** — Three new handlers:
- `handleVariantSelect`: snap marker click → `bridge.setSliderVariant` → await state
- `handleCentsDrag`: optimistic React state update + RAF-throttled `bridge.setSlotCents` (fire-and-forget) + maqam clear guard (once per gesture)
- `handleCentsDragEnd`: `bridge.setSlotCentsFinalize` → await authoritative state

**NoteSlider.css** — Thumb cursor changed from `grab`/`grabbing` to `ns-resize`. Added `.thumb.dragging { transition: none; }`. Snap markers: 7px circles with `cursor: pointer` and hover scale effect.

### Tests

Updated existing tests to set `slot.centsOffset` alongside variant `midiCentsDeviation`. Added three new tests:
1. `centsOffset` drives frequency table independently of `selectedIndex`
2. `centsOffset` drives cents deviation table independently of variant
3. Default `centsOffset` (0.0) produces 12-EDO even when variant has non-zero deviation

### Design Decisions

- **Fire-and-forget bridge pattern**: `setSlotCents` returns void to avoid JSON serialization overhead on every mousemove. Only `setSlotCentsFinalize` (mouseup) returns full state. This keeps MTS-ESP updates at 60fps without flooding the WebView.
- **RAF throttling**: `requestAnimationFrame` used in `handleCentsDrag` to limit C++ bridge calls to ~60fps even if mousemove fires more frequently.
- **Maqam clear guard**: `maqamClearedRef` prevents clearing maqam association on every drag frame — clears once per gesture, reset on mouseup.
- **Shift+drag removed**: Per-note override via Shift+drag interaction disabled (code paths removed from NoteSlider). Per-note overrides still exist in the data model.
- **±200 cents range**: Wider than the typical ±100 to accommodate the full range of Arabic maqam deviations while maintaining useful resolution for fine tuning.

### Follow-up Fix: Preset Modified Styling Restoration

When loading a preset, the cyan modified thumb styling wasn't being restored. Fixed by deriving `modifiedSlots` in `handlePresetClick`:

```typescript
// Derive modified slots by comparing centsOffset to selected variant's default
const modified = new Set<number>()
for (let i = 0; i < 12; i++) {
  const slot = newState.slots[i]
  const variant = slot.variants[slot.selectedIndex]
  if (variant && Math.abs(slot.centsOffset - variant.midiCentsDeviation) > 0.01) {
    modified.add(i)
  }
}
setModifiedSlots(modified)
setIsMaqamModified(modified.size > 0)
```

This compares each slot's `centsOffset` to the selected variant's `midiCentsDeviation`. If they differ beyond 0.01 cents tolerance, the slot is marked as modified and receives the cyan thumb styling.

## Session 21: M4L Session Reload Fix + Real-time Pitch Bend Updates

### What Changed

**M4L mode persistence on session reload** — Fixed issue where the M4L Receiver's mode (MPE/Mono PB) wasn't being applied to the VST3 when reopening a saved Ableton session.

**Root cause**: When a session reloads:
1. Ableton restores `live.tab` (Mode selector) to the saved value silently — no output triggered
2. `plug_vst3` loads a fresh VST3 instance with default mode (MPE)
3. The M4L UI showed correct mode but VST3 was always in MPE mode

**Fix**: Added `pattr` object to store mode value (persisted with M4L patch). On session reload, after VST3 loads (300ms), a delayed bang (500ms) triggers pattr to output the saved mode value to both:
- VST3 (via `pak 1 0.` → `vst~`) — updates file-based registry for Transmitter badges
- JS (via `prepend set_mode`) — sets MIDI processing mode

**Timing optimizations**: Reduced delays from conservative 2000/2500/3000ms to aggressive 300/500/750ms for faster session load.

**Real-time pitch bend for held notes** — Fixed issue where tuning changes weren't heard on held notes in Mono PB mode (MPE was also affected but less noticeable).

**Root cause**: The JS only sent pitch bend on Note On. When tuning data updated via inlet 1, it was stored in the table but not applied to currently-held notes.

**Fix**: Added `updateActivePitchBend(note, cents)` function called when tuning data changes. Checks:
- MPE mode: if note is in `noteToChannel`, send updated PB to that channel
- Mono PB mode: if note matches `monoActiveNote`, send updated PB to channel 1

### M4L Patch Changes (generate_patch.py)

- `delay 2000` → `delay 300` for `plug_vst3`
- `delay 3000` → `delay 750` for metro (tuning polling)
- Added `pattr mode_value @default 0` to store mode persistently
- Added `delay 500` for mode resend after VST load
- Routed `mode_tab → pattr` (store on change)
- Routed `pattr → pak → vst~` (update VST3)
- Routed `pattr → prepend set_mode → js` (update MIDI processor)
- On loadbang: `delay 500 → bang → pattr` re-sends saved mode

### JS Changes (mts_midi_effect.js)

```javascript
// In inlet 1 handler:
if (cents !== oldCents)
    updateActivePitchBend(note, cents);

// New function:
function updateActivePitchBend(note, cents) {
    if (mode === 0) {
        // MPE: check if note is active
        var ch = noteToChannel[note];
        if (ch !== undefined) {
            var bv = calcBend(cents);
            outlet(0, 0xE0 + ch - 1, bv & 0x7F, (bv >> 7) & 0x7F);
        }
    } else {
        // Mono PB: check if this is the held note
        if (note === monoActiveNote) {
            var bv = calcBend(cents);
            outlet(0, 0xE0, bv & 0x7F, (bv >> 7) & 0x7F);
        }
    }
}
```

### Verification

- M4L mode persists correctly across session save/reload
- Transmitter badges update correctly (~500ms after session load)
- Tuning changes heard in real-time on held notes in both MPE and Mono PB modes
- Timing is responsive (no 3-second wait on session load)

## Session 22: Maqam Modification Indicator Fixes

### What Changed

**Snap marker click now respects maqam defaults** — Fixed issue where clicking any snap marker would turn the slider gold, even when selecting a variant different from the maqam's default.

**Root cause**: `handleVariantSelect` was unconditionally removing the slot from `modifiedSlots`, regardless of whether the selected variant matched the maqam's original default.

**Fix**: Added `maqamDefaultPositions` state to track the variant indices when a maqam is applied. In `handleVariantSelect`:
- If clicked variant matches `maqamDefaultPositions[chromaticIndex]` → remove from `modifiedSlots` (turn gold)
- If clicked variant differs → add to `modifiedSlots` (turn/stay cyan)

**Active snap marker color matches thumb** — The selected snap marker dot now uses the same color as the thumb:
- Gold when at maqam default (unmodified)
- Cyan when modified from maqam default

**Preset loading now correctly identifies modified slots** — Fixed issue where loading a modified preset showed gold instead of cyan for slots that differ from the maqam defaults.

**Root cause**: When loading a preset, we compared `centsOffset` to the selected variant's deviation, but for snap-marker-based modifications (where centsOffset equals the variant), this comparison found no difference. We weren't checking if the *variant itself* differed from the maqam's default.

**Fix**: In `handlePresetClick`:
1. First call `bridge.applyMaqam()` to get the maqam's original default positions
2. Store these in `maqamDefaultPositions`
3. Then call `bridge.applyPreset()` to apply the actual preset
4. Compare each slot's `selectedIndex` to `maqamDefaultPositions[i]` to detect variant-based modifications

### Code Changes

**App.tsx**:
- Added `maqamDefaultPositions: number[]` state
- `handleMaqamSelect`: Captures `newState.slots.map(s => s.selectedIndex)` after applying maqam
- `handleVariantSelect`: Compares clicked variant to `maqamDefaultPositions` to determine modified state
- `handlePresetClick`: Applies maqam first to get defaults, then preset, then compares
- `handleSystemSelect`: Clears `maqamDefaultPositions` on system switch

**NoteSlider.css**:
- Added `.note-slider.modified .snap-marker.active { background: #26c6da; }`
- Added `.note-slider.maqam-degree.modified .snap-marker.active { background: #26c6da; }`
- Added `.note-slider.maqam-degree-equiv.modified .snap-marker.active { background: #26c6da; }`

### Verification

- Select maqam → modify slider (drag) → cyan thumb + cyan marker
- Click snap marker matching maqam default → gold thumb + gold marker
- Click different snap marker → cyan thumb + cyan marker
- Save modified preset → load preset → cyan shown for modified slots
- Load unmodified preset → all gold for maqam degrees
