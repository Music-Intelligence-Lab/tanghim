# 2026-02-26 — Session 43: Fix .tanghim Load Modification Detection + Preserve Maqam on Slider Edit

## Summary

Fixed two bugs related to `.tanghim` file loading and maqam modification tracking:

1. **Modification detection on load** — cyan modified-degree thumbs were not appearing after loading a `.tanghim` file with a modified maqam. Root cause: the counter-based event skip in `handleLoadState` was consuming the wrong `tuningStateChanged` event.

2. **Maqam association on slider edit** — modifying a slider previously cleared `currentMaqamId` and `currentDegreeNames`, which broke degree highlights, heptatonic map, and `.tanghim` save/load. Now only the preset is deactivated; maqam association is preserved.

## Bug 1: Counter-Based Event Skip Race Condition

### Symptoms
After loading a `.tanghim` file containing a modified maqam, the slider thumbs showed gold (unmodified maqam degree) instead of cyan (modified maqam degree). The maqam name also lacked the ` *` modification suffix. Slider positions were correctly restored.

### Root Cause
The `handleLoadState` callback used a counter (`isFirstEvent`) to skip exactly one intermediate event (from `loadTuningSystem`'s cleared state) and process the second event (from `restoreStateFromJson`'s restored state). However, a pending `tuningStateChanged` event from a previous action (e.g., slider drag, maqam selection) could arrive between setting the callback and the load events. This stale event consumed the "first event" skip, causing the actual first event (with cleared maqam state) to be processed as the "second" event — which had empty `selectedMaqamId` and `degreeNames`, so no modification was detected.

### Diagnosis
Added `console.log` to the callback, which showed:
```
[loadState] callback Event #2: {maqamId: "", degreeNamesLen: 0, degreeNames: []}
```
This confirmed the callback was processing an event with cleared (intermediate) maqam state, not the restored state.

### Fix: Content-Based Event Matching
Replaced the counter-based approach with content-based matching. The callback now skips ALL events that lack maqam data (`selectedMaqamId` empty or `degreeNames` empty) and processes the first event that has both. This is robust against any number of intermediate or stale events.

For files without maqam data, the callback is consumed after `bridge.loadStateFile()` returns, using the `hasMaqam` flag from C++ to distinguish the two cases.

**Before (fragile):**
```javascript
let isFirstEvent = true
afterSystemSwitchRef.current = (newState) => {
  if (isFirstEvent) { isFirstEvent = false; return false }
  // process newState (might be the wrong event!)
}
```

**After (robust):**
```javascript
afterSystemSwitchRef.current = (newState) => {
  if (!newState.selectedMaqamId || !newState.degreeNames?.length) {
    return false  // keep waiting — intermediate or stale event
  }
  // process newState (guaranteed to have maqam data)
}
// After await: consume callback if file has no maqam
if (!result.hasMaqam && afterSystemSwitchRef.current) {
  afterSystemSwitchRef.current = null
}
```

## Bug 2: buildDegreePaoNameMap Register-Specific Name Overwrite

### Problem
`buildDegreePaoNameMap` maps chromatic index → PAO name for each maqam degree. For a maqam spanning more than one octave (e.g., ascending [rāst, dūgāh, ..., kirdan]), the last degree with a given chromatic index overwrites earlier ones. "kirdan" (C4, register-specific) overwrites "rāst" (C3, base register) for chromatic index 0. Since slot variants only cover MIDI 48-59 (base register), `slot.variants.find(v => v.noteName === "kirdan")` fails → modification not detected for the tonic.

### Fix
Changed to only use the first occurrence per chromatic index (`!result.has(ci)`). Ascending degrees start from the base register, so the first name is always the base-register name that matches slot variants.

## Bug 3: Preserve Maqam Association on Slider Edit

### Problem (pre-existing, fixed in this session)
`setSliderVariant`, `setSlotCents`, and `setNoteVariant` cleared `currentMaqamId`, `currentTranspositionIdx`, and `currentDegreeNames` when the user manually adjusted a slider. This meant:
- Degree highlights disappeared after editing
- Heptatonic map broke after editing
- `.tanghim` save after editing didn't include maqam data (so load couldn't restore it)

### Fix
Only `currentActivePresetIdx` is cleared (deactivates the preset). Maqam ID, transposition index, and degree names are preserved. Comment updated to explain the design intent.
